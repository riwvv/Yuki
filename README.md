# Yuki

Личный ИИ-компаньон, а не голосовая команда «включи свет». Yuki — переосмысление и духовный преемник моего предыдущего проекта, [Jarvis](https://github.com/riwvv/Jarvis), после того как я упёрся в его архитектурный потолок.

> Статус: активная разработка. Голосовой цикл, Host + Servant, MCP-инструменты с подтверждениями, Resource Manager и локальный TTS работают вживую; есть xUnit-тесты ядра и MCP-серверов.

## Зачем ещё один личный ассистент

Jarvis строился на одной LLM, которая отвечала и за разговор, и за выполнение задач — в итоге получалась не столько компаньон, сколько привычная схема умных колонок: «получил команду → выполнил → ответил». Плюс жёсткая зависимость от отдельно установленной Ollama и рваная нагрузка на железо (то простой, то полная загрузка при любом обращении).

Yuki строится вокруг четырёх целей:

- **Скорость** — живой разговор, а не ожидание ответа.
- **Мульти-агентность** — разделение на Host и Servant вместо одной модели на всё.
- **Эффективное использование железа** — осознанное распределение по CPU/GPU, никакого простоя-впустую.
- **Независимость от внешних сервисов** — всё локально, без обязательных сторонних рантаймов.

## Что уже работает

- **Голосовой диалог** — кастомно обученная wake-word модель → детекция речи (VAD) → потоковое распознавание (Vosk) → ответ Host в характере → локальный TTS. Пока Юки говорит, микрофон не включается, поэтому она не слышит сама себя.
- **Окно повторного обращения** — после ответа, когда TTS замолчал и Servant свободен, открывается окно ~7 с: можно сказать следующую фразу **без** «Юки». Wake word возвращается сразу после ответа, так что позвать её в любой момент тоже можно. Тайминги настраиваются в `STT` (`FollowUpWindowMs`, `FollowUpStartDelayMs`, `FollowUpQuietMs`).
- **Host и характер** — разговорное лицо Юки: милая, заботливая, короткая, прямая, с русским сленгом и лёгкой вредностью. Сама решает, ответить или делегировать; результат Servant'a озвучивает своими словами, не выдумывая фактов.
- **Servant с Tool Calling** — фоновый агент-исполнитель: принимает задачу от Host, планирует последовательность вызовов инструментов и возвращает результат. Полный цикл: модель генерирует JSON-вызов → `YukiChatCompletion` превращает его в `FunctionCallContent` для Semantic Kernel → функция выполняется → результат уходит модели для следующего шага. Поддерживаются многошаговые сценарии.
- **MCP-инструменты** — четыре локальных stdio-сервера (`browser`, `media-player`, `system-command`, `file-system`), 26 инструментов: открытие сайтов, управление музыкой и громкостью, системные команды, работа с файлами в разрешённых папках. Всё ограничено списками разрешений: пути, хосты, типы файлов и команды.
- **Подтверждения** — опасные действия не выполняются без явного разрешения. Инструмент возвращает `{"status":"error","cause":"confirmation_required"}`, Servant на этом останавливается, Host спрашивает пользователя; короткое «да / ага / делай» после вопроса продолжает ту же задачу. `confirm = true` нельзя поставить «на всякий случай».
- **Цельная озвучка** — поток токенов ответа собирается в одну фразу (`ResponseTextAggregator`) и только после этого уходит в TTS. TTS сам режет текст на предложения и расставляет паузы; за счёт этого речь не дробится и голосовой цикл быстрее возвращается к слушанию.
- **Структурированный вывод через GBNF** — три грамматики (`tool_calling.gbnf`, `user_interaction.gbnf`, `dialog_only.gbnf`) гарантируют валидный JSON нужной структуры на уровне сэмплера, а не пост-фактум парсингом.
- **Resource Manager** — живой мониторинг свободной VRAM и безопасная «горячая» перезагрузка Host'а при изменении нагрузки на GPU: число GPU-слоёв пересчитывается без потери контекста и без остановки диалога.
- **Читаемые логи и диагностика крашей** — Serilog пишет в консоль, Debug и `logs/yuki-.log` (один файл в день, 14 файлов, UTF-8 без BOM). Необработанные исключения UI, фоновых потоков и задач попадают в лог со стеком.

## Как это выглядит в использовании

```
«Юки, открой ютуб»            → open_url, без лишнего подтверждения
«Юки, сделай громкость 50%»   → «Эй, правда на пятьдесят ставим?»
«Да, делай»                   → громкость установлена, окно повторного обращения
«Юки, выключи компьютер»      → только с прямого разрешения, confirm = true
«Сверни все окна»             → можно без «Юки», если это сразу после её ответа
```

Ответы инструментов считаются **данными, а не инструкциями**: просьбы внутри них изменить правила, показать токен или открыть локальный путь игнорируются.

## Архитектура (коротко)

- **Host** — разговорное лицо Yuki. Решает, отвечать самой или делегировать Servant'у, ведёт диалог в характере. Использует `user_interaction.gbnf` для ответа (текст + опциональный tool call) и `dialog_only.gbnf` для системных событий. История очищается при достижении лимита с пересозданием инференс-движка для сброса KV-cache.
- **Servant** — специалист по выполнению задач и tool calling, с инвентарём MCP-инструментов. Для изоляции контекста между задачами используется `StatelessExecutor`: каждая задача начинается с чистого состояния. `YukiChatCompletion` реализует `IChatCompletionService` Semantic Kernel и ведёт цикл вызова инструментов с валидацией аргументов.
- **MCP** — инструменты живут в отдельных процессах и общаются по stdio; `McpManager` подключает серверы при старте и кэширует список инструментов. Стартаповый шум фильтруется: ошибки уходят в `Warning`, рутина — в `Debug`.
- **Голосовой цикл** — `VoiceInteractionService` связывает wake word, VAD, Vosk, TTS и Servant. `EndBusy()` возвращает wake word, а отдельный waiter дожидается тишины TTS и свободного Servant'а перед открытием окна повторного обращения.
- Обе роли — независимо настроенные экземпляры одной и той же LLM-инфраструктуры (llama.cpp), не разные модели ради разных задач.
- **Resource Manager** отвечает за то, какая модель когда загружена и сколько слоёв уходит на GPU; модели живут ровно столько, сколько реально работают.

## Ключевые технические решения

- **GBNF-грамматики** — принудительная генерация JSON заданной структуры на уровне сэмплера. `user_interaction.gbnf` ограничивает `args` полем `"task"`.
- **Stateless-инференс для Servant** — чистый KV-cache в начале каждой задачи, что стабилизирует многошаговый Tool Calling.
- **Валидация tool call в коннекторе** — до `InvokeAsync` проверяется существование функции и обязательных параметров; ошибка возвращается модели, чтобы она исправилась без прерывания цикла.
- **Nudge-логика** — при пустом ответе модель получает явную инструкцию и повторяет генерацию ограниченное число раз, затем идёт осмысленный fallback.
- **Протокол подтверждений** — реальные ответы инструментов (`done` / `error` с `cause` и `description`) описаны в промптах; `confirmation_required` — стоп-сигнал для Servant'а и вопрос от Host'а.
- **Списки разрешений** — только разрешённые хосты для URL, папки и типы файлов, whitelist системных команд; `open_url` для доверенных сайтов работает без подтверждения.
- **Сборка ответа перед TTS** — устранение дробной озвучки по токенам и огромной очереди синтеза.
- **Параметры сэмплинга** — `RepeatPenalty`, `PresencePenalty`, `FrequencyPenalty` защищают от зацикливания в длинном контексте.

## Структура репозитория

| Папка | Что внутри |
|---|---|
| `Yuki/` | WPF-приложение, `AppBootstrap`, `appsettings.json`, Serilog |
| `Yuki.Core/HostAgent`, `Yuki.Core/ServantAgent` | два агента и их промпты в `Yuki.Core/Prompts` |
| `Yuki.Core/STT`, `Yuki.Core/TTS` | wake word, VAD, Vosk, аудио, синтез речи |
| `Yuki.Core/MCP`, `Yuki.Mcp.*` | клиент MCP и четыре сервера инструментов |
| `Yuki.Core/ResourceManagement` | мониторинг VRAM и безопасная перезагрузка |
| `Yuki.Core/Wrappers` | llama.cpp-инференс и коннектор к Semantic Kernel |
| `*.Tests/` | xUnit-тесты ядра и MCP-серверов |

## Стек

- **.NET 10 / WPF** (`net10.0-windows10.0.19041.0`) — основное приложение.
- [**LLamaSharp**](https://github.com/SciSharp/LLamaSharp) (llama.cpp) — локальный инференс LLM.
- **Microsoft Semantic Kernel** — оркестрация инструментов; кастомный `YukiChatCompletion` связывает его с LlamaSharp.
- **Model Context Protocol** — stdio-серверы инструментов (`browser`, `media-player`, `system-command`, `file-system`).
- **Vosk** — потоковое распознавание речи (STT).
- **ONNX Runtime** — wake word, VAD и TTS (Supertonic 3), всё оффлайн.
- **LibreHardwareMonitorLib** — живой мониторинг VRAM.
- **Serilog** — консоль, Debug и файловые логи.
- **xUnit** — тесты.

## Требования и ресурсы

- Windows 10 19041+ / .NET 10 SDK.
- LLM в формате `.gguf` — положите в [`Yuki.Core/LlmModels`](Yuki.Core/LlmModels/README.md) и укажите имя в `Host:ModelName` в `appsettings.json`. Разработка велась на Qwythos-9B Q4_K_M и RTX 4060 8 GB с запасом 1–1.5 GB VRAM.
- TTS-ресурсы (`assets.zip` из [Releases](https://github.com/riwvv/Yuki/releases)) — распакуйте по инструкции в [`Yuki.Core/TTS/Resources/assets`](Yuki.Core/TTS/Resources/assets/README.md).
- Модель Vosk скачивается автоматически при первом запуске в `%LOCALAPPDATA%\Yuki\Models\vosk` (нужен интернет один раз). ONNX-модели wake word и VAD уже лежат в репозитории.

## Настройка и логи

Основные секции `Yuki/appsettings.json`:

- `Host` — модель, контекст, история и параметры сэмплинга.
- `Servant` — лимиты итераций/подсказок, грамматика tool calling, размер контекста.
- `STT` — Vosk, тайминги тишины и окна повторного обращения.
- `WakeWord`, `AudioCapture`, `ResourceManager` — порог, усиление, VRAM и частота проверки.
- `Serilog` — уровни логирования; для отладки Host'а добавьте override `Yuki.Core.HostAgent.Services.HostAgentService: Debug`.

Логи лежат рядом с исполняемым файлом: `bin/Debug/net10.0-windows10.0.19041.0/logs/yuki-YYYYMMDD.log`.
